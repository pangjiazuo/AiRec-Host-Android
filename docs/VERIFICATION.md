# 安卓录像主机测试记录

## 1.0.1 单路负载优化 · 2026-09-14

测试保持 AHD1 录像、NPU 识别和本机实时画面开启，其他四路无信号。CPU 以整块六核 CPU 满载为 100%，APK 合计包括主进程、WebView 和识别进程。

| 项目 | 优化前 | 优化后样本 |
| --- | --- | --- |
| APK CPU 合计 | 35.91% | 11.78%～12.46% |
| 整机 CPU | 41.45% | 约 20%～21% |
| 本机预览 | 约 16 FPS | 约 16 FPS |

- 本机视频改用 SurfaceView 直显；VPU H.264 录像和 RKNN NPU 推理保持开启。没有降低录像目标帧率或关闭识别。
- 完整 MP4 检查：H.264、1280×720、60.78 秒、1488 帧，平均 24.48 FPS。短时状态统计会波动。
- Windows 网络预览收到 311 帧，平均 15.73 FPS；断开后观看计数归零，JPEG 自动恢复约 2 FPS 的识别/截图供给，本机仍约 16 FPS。
- Java 单元测试、网页时间轴/配置合并测试通过；实际 APK 的详情、全屏、切页、弹层、回放进度和预览恢复检查通过。主机屏幕已核对原生视频及按钮位置。
- 切页恢复的帧率计数已单独重置，避免把离开页面的时间算进新一轮帧率。测试需等待至少一个统计周期。
- DMA-BUF 直接导入在 APK 环境不可用，试验实现已移除。当前仍是 GPU 纹理上传与硬件编码，不能宣称采集零拷贝。
- **尚未保证稳定低于 10%**，多人远程观看、五路实拍和长期运行仍需单独验证。现场图片与原始日志仅保存在工作区 data 下，没有加入仓库。

2026-09-14：显示版本统一为 **1.0.0**，内部 versionCode 增至 3；关于页面、启动日志与健康接口同步更新。旧界面验收仍按原版本记录。

# 测试记录

2026-09-12，版本 0.1.0。测试设备为 RK3399PRO 五路 AHD 开发板，Android 9 / API 28，ARM64；仅 AHD1 接入摄像头。这是实机验证版，尚未完成五个摄像头同时接入和长期运行测试。

## 已通过

| 项目 | 结果 |
| --- | --- |
| 安装与本机操作 | APK 覆盖安装成功；主机屏幕可显示五路通道、设备信息、设置和真实录像回放 |
| 实际视频 | AHD1 为真实画面，720p H.264；多次观察录像约 22～25 帧/秒、预览约 16 帧/秒，导出及测试操作期间曾短时降至约 14 帧/秒，尚非稳定 25 帧验收 |
| 无信号 | AHD2～5 的四宫格源可以读取，无信号时不录像、不识别，不阻塞 AHD1 |
| 局域网 | 同时六个预览连接约 15.8～16 帧/秒；状态请求约 27 毫秒 |
| NPU | YOLOv5s ReLU 模型在 NPU 上成功运行；官方测试图识别出 3 个人和 1 辆车，实际摄像头也持续推理 |
| 五路编码 | 四个 VPU 编码器加一个软件编码器同时输出，各完成 90 帧；这是合成输入测试，不代表五路实拍性能 |

| 循环录像 | 独立测试目录验证仅清理本应用最旧媒体，保留新媒体与无关文件 |
| 回放与时间轴 | 已完成 MP4 可播放、定位；验证跨午夜录像与跨查询边界的停留事件 |
| 接口与日志 | 配置校验、事件分类、视频分段读取、日志 ZIP、并发预览测试通过 |
| 本机导出 | 已通过系统文件选择器保存约 14 MB 的实际 MP4，文件名与扩展名正确 |
| 开机启动 | 安装更新后实际重启，自动进入主机预览界面，AHD1 自动录像、NPU 恢复推理，局域网接口可访问 |

模型随包提供，SHA256：

`885edffddd3195dcd382a1de1348fbaec5652bc530e4c49ba47a8fe3b3f41826`

## 需要继续确认

- AHD2～5 的物理插口与四宫格区域顺序，需要逐路接入摄像头确认。
- 五路实拍时的软件编码负载、识别速度和温度，不能用单路或合成输入结果代替。
- 外置 SD 卡插拔、长时间连续录像、异常断电恢复还需要专项实测。正在写入的 MP4 在断电时可能丢失。
- 当前适配依赖固件已有的 `su 0` 和视频驱动；普通无 root 的 Android 设备不能直接使用本程序采集这组 AHD 接口。

开发中曾因异常的视频链路与重复启动采集触发一次旧版内核崩溃，开发板自动重启。现已恢复正确的视频链路，并在启动采集失败时停止自动重试；后续测试未再次观察到该问题，但这不等同于已完成长期稳定性验证。

## 复测入口

- `scripts/build.ps1 -Offline`：构建 APK 并运行跟踪单元测试。
- `scripts/smoke_test.py --url http://开发板IP:8080`：检查局域网接口、媒体读取和并发预览。
- `app/src/androidTest/`：板卡上的 NPU、编码器、信号与存储测试，使用独立测试目录。

现场画面和完整诊断输出只保留在开发电脑的私有测试目录，不放入仓库。
